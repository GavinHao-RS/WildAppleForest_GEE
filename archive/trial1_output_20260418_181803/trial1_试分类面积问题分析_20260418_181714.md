# Trial1 试分类面积问题分析

时间戳：2026-04-18 18:17:14 +08:00

## 1. 实验背景

本次 `trial1` 基于主 notebook [wildapple_localrun_python.ipynb](d:/CODE/VS__Project/GEE/WildAppleForest_GEE/wildapple_localrun_python.ipynb) 的 Trial-GEE 分类流程执行，已完成：

- `7A`：Trial 特征组装、拟合特征补建、训练样本重采样、GEE 端随机森林训练
- `7B`：提交 raw / smoothed 分类结果到 GEE asset
- `7C`：基于导出 asset 的面积统计

当前面积统计结果显示：

- `class 1 / Wild Apple Forest` 面积约 `1.69e+06 ha`
- 若按预期只应占研究区总面积的千分之几，则该结果明显偏大

这说明问题不在面积统计公式本身，而在更前面的训练样本定义与样本结构。

## 2. 当前暴露出的核心问题

当前 `class 1` 不是略偏大，而是明显扩张过度。  
从训练样本与流程结构来看，这一问题主要来自以下三个方面：

1. `class 1` 样本数量被系统性放大
2. 正样本 buffer 扩样导致正类空间定义过宽
3. ring / hard negative 尚未真正纳入训练集

## 3. 样本构建问题

### 3.1 正负样本结构严重不对称

当前样本构建中：

- `class 1` 来源包括：
  - 野苹果原始点
  - 矩形样地规则采样
  - 野苹果点 buffer 后形成的小面区域再采样

- 负类来源主要包括：
  - WorldCover 分层采样点

这两类来源在空间结构上不对称：

- 正类：局部高密度、重复采样、空间相关强
- 负类：稀疏、分散、包含大量容易区分的样本

其直接后果是：

- 模型更容易把局部相似背景学习成正类
- 模型在整图上更愿意向外扩张 `class 1`

### 3.2 正类数量相对于负类过多

前面主流程输出已经表明，清洗后 `class 1` 大约 `904`，而其他单类仅约 `147-150`。

这意味着：

- `class 1` 在训练样本中处于明显过量状态
- 随机森林会更倾向于在边界模糊区输出正类

因此即使混淆矩阵没有完全失控，整图面积也会显著虚高。

## 4. buffer 扩样问题

### 4.1 buffer 把点标签扩成了片标签

当前野苹果正样本点经过 buffer 扩样后，本质上形成了如下隐含假设：

> 正样点附近一个固定半径范围内的像元，都可以视为野苹果林像元

这个假设在实际景观中往往过强，尤其在：

- 林缘
- 谷地过渡带
- 林地与灌丛、草地的镶嵌区域
- 正样点附近混合像元区

会导致两个问题：

- 混合像元被当作纯正类
- 邻近但并非正类的像元也被纳入正类

模型随后学到的是“宽松版野苹果林”，而不是高纯度的野苹果林。

### 4.2 `max_pixels_per_group` 只能抑制过量重复，不能解决标签污染

当前流程使用 `max_pixels_per_group` 对每个 `group_id` 保留像元数做上限控制，这确实能缓解：

- 单个原始点扩出太多像元
- group 内重复样本过度代表

但它不能解决：

- buffer 内本来就存在的标签纯度问题
- 正类空间定义过宽问题

所以即使 group 上限生效，污染过的正类样本仍然会推高整图 `class 1`。

### 4.3 矩形样地规则采样可能进一步放大局部正类偏置

矩形样地如果足够高纯度，会提高正类样本稳定性。  
但如果该样地区域包含：

- 斑块边缘
- 林隙
- 过渡带

则规则采样会进一步放大正类定义过宽的问题。

## 5. ring / hard negative 缺失问题

### 5.1 当前负类更多是“泛负样本”，不是“难负样本”

WorldCover 补样能提供很多明显不是野苹果林的负类，但这对控制 `class 1` 假阳性并不够。

真正困难的负类应主要来自：

- 野苹果林附近的其他森林
- 野苹果林附近的草灌
- 生境接近、但标签为负类的谷地林地或相似植被

如果这些样本缺失，模型就学不会“如何拒绝看起来很像野苹果林的非野苹果林区域”。

### 5.2 没有 ring，模型就不知道正类边界外面长什么样

ring 的核心作用不是简单增加负类数量，而是补如下样本：

- 空间上靠近正类
- 生境上接近正类
- 但标签明确为负类

当前如果还没有把 ring hard negative 真正接入训练集中，模型能学到的主要是：

- 正类中心区域
- 容易负类

却学不到：

- 正类边界外的相似负类

这会直接导致整图上 `class 1` 外溢。

## 6. 为什么平滑后 `class 1` 面积更大

当前试分类结果中，平滑后 `class 1` 面积甚至比 raw 略大，这很说明问题。

这意味着：

- `class 1` 不是由大量零散噪声点组成
- 而是已经形成了广泛、连续的预测区域

在这种情况下，`focal_mode` 会进一步把周边零散非 `class 1` 吸并进大斑块，因此面积继续上升。

这也说明当前问题重点不在后处理，而在分类前的样本定义。

## 7. 当前最可能的主因排序

按影响强弱排序，当前 `class 1` 面积虚高最可能的主因是：

1. 正类 buffer 扩样使 `class 1` 定义过宽
2. 正类样本数量明显多于各负类
3. 当前训练集中缺乏 ring 驱动的 hard negatives
4. WorldCover 负样本更偏“容易负样本”
5. 矩形样地规则采样可能放大局部正类偏置

## 8. 后续优先调整方向

当前最值得优先调整的不是 RF 参数，也不是面积统计尺度，而是样本策略本身。

建议后续按如下顺序推进：

1. 缩小 `class 1` buffer 半径
2. 下调 `max_pixels_per_group`
3. 将 ring hard negative 真正纳入样本构建
4. 将 hard negative 优先聚焦到：
   - Other Forest
   - Grassland/Shrub
   - 谷地附近相似地类
5. 后续重点盯住 `class 1 precision`，而不是只看 OA

## 9. 结论

本次 `trial1` 面积异常偏大的核心原因，不是面积统计函数本身，而是：

> 当前样本构建中，`class 1` 被 buffer 扩样和局部重复采样显著放大，而 ring / hard negative 尚未真正加入训练，使模型在整图上对 `class 1` 产生强烈外扩倾向。

因此，本次试分类结果应视为：

- 一个成功跑通 Trial-GEE 导出与统计流程的诊断结果
- 不是可直接用于正式汇报的野苹果林面积结果
